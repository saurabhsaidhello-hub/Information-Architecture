Blueprint

Imagine walking into a supermarket where nothing is organized. Shampoo sits next to fresh fish, bread hides behind the batteries, and there are no signs. You'd leave frustrated, probably without what you came for.

Now think of the last time you used Instagram, Spotify, or Google Maps. You probably found what you wanted without thinking about it. That's not luck. Someone designed that experience, and the discipline behind it is called Information Architecture (IA).

( What is it )

Information architecture is the art and science of organizing, labeling, and structuring information so people can find what they need and know where they are.

If an app is a building, visual design is the paint and furniture. IA is the floor plan: the rooms, the hallways, and the signs on the doors.

Same items, different organization
( Three questions )
01
Where am I?
Titles, highlighted menus, and breadcrumbs tell you your location.
02
What can I do here?
Obvious buttons and logical options show the possible actions.
03
Where can I go next?
Menus and related links point the way forward. If you feel lost, one of these went unanswered.
Rooms are screens. Hallways are navigation.

( The cafeteria story )

A messy cafeteria scatters hot food, drinks, and desserts at random. An information architect would observe where students get stuck, group items into zones, label them in plain words, and test the result. The food never changed. Only the organization did.

Same food. Clear zones. One path.

Here are four examples of information architecture, all drawn for one imaginary app: Campus Eats, where students order lunch.

( 01 Sitemap )

A sitemap is a bird's-eye view of every screen in a product and how they are grouped. It is the first thing an information architect draws.

Sitemap: every screen, grouped in levels
( 02 User flow )

A user flow follows one person completing one task, step by step, including the decisions along the way. It shows where things can go wrong.

User flow: one task, with a decision point
( 03 Wireframe )

A wireframe is a simple black-and-white layout of one screen. It decides what goes where, with no colors or photos to distract from the structure.

Wireframe: structure first, style later
( 04 Taxonomy )

A taxonomy is the agreed system of categories and labels for your content. Categories form a hierarchy, and tags describe attributes that cut across it.

Taxonomy: categories for browsing, tags for filtering

Good IA has to survive every screen size. These practices keep one structure working from desktop to phone.

Same content and same priority order on every screen
( Best practices )
01
Keep one structure everywhere
Don't build a separate mobile site. Keep a single content structure and let the layout adapt. You update content once, and every device shows the change.
02
Put the essentials first
Decide what matters most and keep it at the top on small screens. A restaurant site, for example, leads with location, opening hours and a booking button, and puts the full menu below.
03
Simplify navigation on small screens
Collapse long menus into a hamburger, an accordion or tabs, but keep the same labels and the same order. Build menus from real lists so screen readers understand them.
04
Use flexible grids, not fixed widths
Let columns grow, shrink and wrap with the screen. This one rule gives you many columns on a desktop and a single column on a phone.
.grid{ display:grid; grid-template-columns:repeat(auto-fit,minmax(250px,1fr)); gap:16px; }
05
Make images and text fluid
Cap image width at 100% of its container so nothing overflows, and let font sizes scale between a minimum and a maximum so text stays readable.
img{max-width:100%;height:auto} h1{font-size:clamp(1.5rem,5vw,3rem)}
06
Start small, then scale up
Design the phone layout first, then add space and columns for bigger screens. This forces you to rank your content, which is the heart of IA.
07
Use semantic HTML
Real headings, lists and landmarks let assistive technology read the structure you designed. Good IA should be understood by machines too.
08
Test on real devices
Use browser developer tools and, when you can, real phones. Look for tiny text, hard-to-tap buttons, cluttered layouts and heavy images that load slowly.

( Try it yourself )
01 — The Junk Drawer Challenge
Sort 20 random items into groups, then compare with a classmate. Did you group them the same way?
02 — Menu Detective
Map a favorite app's main menu on paper. What is the logic? What would you change?
03 — Label Swap
Rename five confusing buttons from a website you dislike. Ask a friend which versions they prefer.
( The big idea )

IA is about empathy: how does this person think, and how can I make their path clear?
